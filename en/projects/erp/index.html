Team project

PremieRpet Operations ERP

A team development project where I coordinated three contributors new to programming.

Context

PremieRpet Operations ERP covers inventory, movements and traceability. Its repository identifies it as an integrative academic project.

My contribution

Contributed to development and coordinated three beginner programmers. This involved collaboration and technical guidance within the project, rather than a formal management position.

Engineering decisions

  1. Full-stack application

    The project uses Next.js, React and TypeScript, with API routes, server-side business rules and shared persistence through Firebase Admin.

  2. Consistency and access

    The repository documents access control, auditing, version checks and conflict handling for critical resources. These are features of the collective project.

  3. Gradual evolution

    Legacy resources coexist with dedicated routes. The documentation explains synchronization and normalization considerations without presenting the architecture as finished.

Quality & limitations

Documented automated validation focuses on the backend, including critical flows and business rules. Frontend coverage is not yet equivalent.

Development supports local persistence; the production backend requires configured Firebase Admin credentials. Coexisting legacy and dedicated resources require care with synchronization and conflicts.
